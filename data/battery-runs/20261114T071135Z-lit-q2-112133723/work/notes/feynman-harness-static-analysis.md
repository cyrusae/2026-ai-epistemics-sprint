## What the harness does enforce mechanically
- Artifact existence and naming are conventions in prompts (e.g. `/deepresearch` requires plan, draft, cited, final, provenance paths), but nothing in the shipped code verifies those files exist or are non-empty.
- `scripts/check-pi-rpc.mjs` boots the CLI in RPC mode and asserts that commands/prompts/skills/agents loaded. It is a packaging smoke test, not an output-quality eval.
- Session transcripts are JSONL with `tool_execution_start/end`, usage, and model-change events — usable for observability, not gated on.

## What is policy-only (LLM self-discipline)
- "Never invent results"; "every quantitative claim must trace to a source"; "say verified only when checked"; "remove unsourced claims"; "no orphan citations"; "URL or it didn't happen".
- These are distributed across SYSTEM.md and the four agent prompts, with overlap and some tension (e.g. verifier: remove unsourced claims vs. writer: preserve caveats).
- Consequence: compliance is observable in transcripts but not guaranteed by construction.

## Structural properties relevant to eval quality
1. **No dataset/solver/scorer abstraction.** Unlike Inspect-style evals, a task is a prompt + tools, and the "score" is a written artifact judged by an LLM or a human. There is no sample table, no per-sample target, no metric aggregation.
2. **Single-run by default.** No epochs/repetitions, no variance reporting, no confidence intervals.
3. **Correlated grader risk.** The lead, researcher, verifier, and reviewer run on the same configured model unless the caller overrides the model per child. Same-family writer and verifier errors can correlate.
4. **Audit trail depends on the parent's instruction.** The verifier's default output contract requires citations and a Sources section; it does not require a corrections log. Silent correction is therefore possible.
5. **Strong provenance affordances.** The verifier is explicitly told to fetch every URL, cross-check DOI/arXiv IDs against two indexes, and verify meaning rather than topic overlap. This is unusually explicit for an agent harness.
6. **Degraded-mode contract.** SYSTEM.md requires a `Blocked`/`Unverified` artifact instead of chat-only failure — good for eval completeness, but the label is self-assigned.

## Hypothesis generated by the static read
H1: On bounded drafts with supplied source excerpts, the verifier will detect most contradicted claims.
H2: It will be weaker on plausible-but-unsupported claims, because nothing in the notes contradicts them and removal requires an explicit absence check.
H3: Detection will be under-reported unless the parent asks for a claim-level audit, because the default output contract has no corrections section.
