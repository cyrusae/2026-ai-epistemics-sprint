## Consistency and provenance notes

1. **Internal inconsistency on the baseline.** In §4.3 the paper writes: "For HumanEval and MBPP Python, the baseline pass@1 accuracies are relatively similar, **82% and 80%**, respectively." [3] That 82% conflicts with Table 1's 80.1 for HumanEval (and with Table 2's Base = 0.80, and with the abstract's 80%). If quoting a baseline, use **80.1 (Table 1) / 80% (abstract)**; the 82% sentence appears to be an error or refers to a different run, but the paper does not explain it. [2][3]
2. **Version dependence of the headline.** The v1 abstract describes only ALFWorld and HotPotQA ("success rates of 97% and 51%") and contains no HumanEval/91% sentence [4]. The quoted sentence belongs to the later v4 abstract. A citation to "Shinn et al., 2023" should therefore specify v4 (or the NeurIPS 2023 version) if the 91% claim is attributed to the abstract.
3. **Provenance of 80.1 is not given.** Table 1 labels 80.1 "(GPT-4)" but cites no source or evaluation harness for that number [2]. OpenAI's GPT-4 Technical Report, Table 2, reports **67.0%** 0-shot HumanEval pass@1 [7], so 80.1 is not the GPT-4 report's headline figure; the Reflexion paper does not explain the discrepancy (different prompt/harness/temperature is plausible but unstated — inference). Treat 80.1 as the paper's own attributed baseline, not as the GPT-4 report's number.
4. **Repo corroboration of set size, not exact score.** The released GPT-4 HumanEval run script uses `--pass_at_k "1"` [5], and the released log contains 164 unique HumanEval task IDs with 150 marked solved (91.5%) [6]. That is close to, but not identical with, the Table 1 value of 91.0 (149/164 = 90.9% would round to 91.0), so the log should be treated as corroboration of the 164-problem evaluation set and the pass@1 setting, not as an exact reproduction of the table. This last comparison is my arithmetic, not a paper claim.
5. **What "pass@1" means here.** Table 1's caption says the base strategy is "a single code generation sample" [2]. Reflexion reports the pass@1 of its final submitted solution after internal trial/self-reflection iterations — it is not pass@k over k independent final samples. §4.3 explicitly distinguishes methods that "rely upon ground truth test cases that invalidate pass@1 eligibility" [3].

## Findings

The paper's headline HumanEval claim is **91.0% pass@1** in Table 1, rounded to **91%** in the abstract [1][2]. The comparator is explicitly labelled **80.1 (GPT-4)** in Table 1, rounded to **80%** in the abstract [1][2]. The metric is **pass@1**: the table caption names it, §4.3 says the implementation is "eligible for pass@1 accuracy reporting," and the released script passes `--pass_at_k "1"` [2][3][5]. It is not pass@k over multiple final samples; Table 1 describes the base strategy as "a single code generation sample" [2].

HumanEval contains **164** problems according to its originating paper, which says it evaluates "a set of 164 hand-written programming problems" [8]; the released dataset file also contains 164 records [9]. The Reflexion paper does not itself state a count, so the count must be sourced externally [2][3].

The verbatim abstract sentence is: **"For example, Reflexion achieves a 91% pass@1 accuracy on the HumanEval coding benchmark, surpassing the previous state-of-the-art GPT-4 that achieves 80%."** [1] This sentence is version-specific: it is absent from the v1 abstract, which reports only ALFWorld/HotPotQA success rates [4].

Two caveats matter for anyone quoting these numbers. First, §4.3's prose says the HumanEval and MBPP Python baseline accuracies are "82% and 80%," which conflicts with Table 1's 80.1 and Table 2's Base = 0.80 (an internal inconsistency; the 82% is unsupported by the tables) [2][3]. Second, the 80.1 GPT-4 figure is uncited in Reflexion, while OpenAI's GPT-4 report lists 67.0% 0-shot HumanEval pass@1 [7]; the two are not the same measurement, and the paper does not explain its baseline's harness (inference: prompt/temperature differences are the likely cause, but this is not stated).

## Coverage status

- **Checked directly:** v4 abstract page, v4 PDF (Table 1, §4.3, Table 2, Table 4), v4 HTML, v1 abstract, the Reflexion run script and HumanEval result log, the Chen et al. 2021 PDF (§2.2), the released HumanEval JSONL, and the GPT-4 technical report Table 2.
- **Verified by direct count:** HumanEval = 164 records (openai/human-eval); Reflexion log = 164 unique task IDs, 150 solved.
- **Uncertain / unresolved:** the provenance of the 80.1 GPT-4 baseline (no citation, no harness description); whether the 91.0 table value comes from exactly the released log (log gives 91.5%); whether the "82%" sentence refers to a different run. These do not change the five requested answers.
- **Not done:** I did not audit the NeurIPS proceedings PDF (paywalled/alternate version); all quotes are from arXiv v4. I did not re-run any code.
